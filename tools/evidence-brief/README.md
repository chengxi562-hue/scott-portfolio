# 循据 · Evidence Brief

**公开测试版 0.1**。为使用 AI 做商业、营销和金融资料研究的人，把「说法—证据—复核缺口」整理成可以继续工作的简报。

[在线使用](https://yichengxi.cn/tools/evidence-brief/) · [反馈问题](https://github.com/chengxi562-hue/scott-portfolio/issues)

## 一个完整用法

1. 写下研究问题，选择营销、金融或 AI 产品场景。
2. 粘贴 AI 回答中的具体说法，每个非空行变成一条待验证假设；按实际情况改为事实陈述或分析推断。
3. 为每条说法补充原始链接、日期、摘录和上下文，标记支持、反驳或仅背景。
4. 打开原始材料亲自核对，再记录人工复核。完整词与数字边界也参与摘录核对，避免把 100 中的 10 当成相同数字。
5. 预览并导出 Markdown 简报，或生成任务文本粘贴到自己的 AI。资料不会自动发送给任何模型。
6. 导出 JSON 备份可再次导入；导入会严格验证格式与上限，不执行其中代码。

## 能力与限制

- 浏览器内处理，无账号、密钥、收费模型、抓取服务、追踪脚本或实时行情。
- `sessionStorage` 只保存本标签页。关闭标签页、清除网站数据或浏览器限制都可能造成丢失；保存失败会明确提示。重要内容请导出 JSON。未保存的表单不会偷偷混入已保存的简报。
- 来源性质和支持关系是使用者标记，**不是平台认证**。HTTPS、官方域名、文字命中均不证明一个结论真实。
- 摘录只与用户粘贴的原文比较；不自动读取远端网页。Unicode 空白可折叠，数字、否定词、符号不做模糊归一化。中文短片段缺少完整语句边界时可能保守判不匹配，请粘贴完整原句。
- 已记录复核不等于已证实。不自动判断因果关系，不推荐证券，不给胜率/收益保证。
- 目前中文界面；个人网站的中英切换不代表本工具已完整双语。
- JSON 备份包含用户粘贴的原文；Markdown/AI任务只包含摘录和元数据。复制给其他 AI 前自行确认资料是否适合发送。
- 一次最多 30 条说法，每条 10 个来源；导入上限 2 MB，原文总量上限 300,000 字。无云同步和协同编辑。

## 示例与真实来源

内置示例研究「AI 商业研究工具的定位」，同时演示完整记录、只有背景材料、缺少证据的假设。示例中的市场需求和节省效果没有被真实用户实验验证。

- [SEC — Accessing EDGAR Data](https://www.sec.gov/search-filings/edgar-search-assistance/accessing-edgar-data)：公众可免费获取申报信息。示例仅使用短摘录。资料页列出的发布日是 2021-03-23，另有后续复查/更新日期；本例记录的是发布日。
- [Zotero — Notes](https://www.zotero.org/support/notes)：作为现有笔记工具的背景来源，示例没有借此证明用户需求或节省效率。
- 示例查看日期固定为 2026-09-19，之后不会自动更新。需要使用者重新查看来源。

## 本地运行与验证

无需安装依赖或构建。克隆仓库后，在仓库根目录运行：

```sh
python3 -m http.server 8080 --bind 127.0.0.1
```

打开 `http://127.0.0.1:8080/tools/evidence-brief/`。浏览器需支持 ES modules、原生 dialog、sessionStorage 和 Unicode property escapes。不要直接双击 HTML（模块在 file:// 下可能不工作）。

核心测试：

```sh
node --test tools/evidence-brief/core.test.mjs
```

`core.mjs` 是纯函数；`app.mjs` 是交互/标签页存储/下载；`index.html` 与 `app.css` 是页面。核心不联网，页面 CSP 的 `connect-src 'none'` 禁止脚本外连；用户主动打开原始来源是正常页面导航。没有导入第三方客户端库。

## 与原项目的关系

本工具承接个人投研的证据记录、知识库的引用回查、AI 协作的交付验收思想，公开实现为独立模块。**不是把私人投研后台改名公开**，也不包含会员配置、账户持仓、原始视频转写库或私人档案。可公开使用的范围就是本目录实现的功能。

## 持续维护与反馈

本版成功条件是：真实使用者能独立完成一份可追溯简报，且导入/导出不丢信息、缺失证据不被标成完成。尚未完成外部用户可用性验证，不声称已有用户数或效率提升。

反馈时请提供浏览器、复现步骤、预期与实际行为、可脱敏的最小 JSON。不要提交私人资料、账号、密钥或未经授权的长篇原文。

后续优先级：先根据真实试用改进录入成本与错误提示；再评估文档/时间戳导入与资料变化后复核。自动网页抓取、模型调用、云协作需独立验证成本、权限和隐私后再做，不承诺后台自动持续运行。

发布要求：核心回归、正常与反向浏览器操作、手机视图、导入导出及未保存草稿保护、公开资源实测。修改核验规则必须先写会在旧实现失败的反例。
