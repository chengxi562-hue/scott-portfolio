# 协作计划设计器 · Task Brief

**2026-09-23 手动交接版。** [在线入口](https://yichengxi.cn/tools/task-brief/) · [反馈问题](https://github.com/chengxi562-hue/scott-portfolio/issues)

中文浏览器工具，把目标、材料、限制、交付和验收写清楚，再把自己使用的 AI 产物逐步接回来。生成任务文本、保留实际产物与人工判断，导出完整记录。无需账号、API Key，不调用模型、不上传资料，也不需要个人站点所有者的执行器。

## 手动交接：从任务到实际产物

1. 填写任务信息后点击“开始手动交接”。研究/写作使用“计划 → 初稿 → 复核”；代码任务保持单步。
2. 复制本步任务，交给自己使用的 AI。返回后粘贴真实产物并保存；只有保存了当前任务对应的上游产物，下一步任务才可复制。
3. 初稿任务携带实际计划；复核任务携带实际计划、初稿和原验收标准。不会把阶段标记或“已完成”当成通过证明。
4. 对照每条验收标准人工选择“通过 / 待修改 / 未核验”。通过与待修改须填写依据；默认未核验，AI 复核意见不会自动替你确认。
5. 下载交接 JSON 以完整恢复；导出 Markdown 带走任务、各阶段产物、人工判断及旧记录。Markdown 不能恢复本页输入。

任务或上游产物改变后，下游记录和旧人工判断失效，原稿与依据保留供重新核对。改回原文也不会自动恢复旧通过。改变任务类型时旧流程产物保留；修改验收标准时旧判断归入历史。任务暂时超限时暂停依赖编辑，避免输入在修复后被覆盖。产物与验收依据的超限粘贴整段拒绝，保留原输入，不静默截断。

一项完整使用结果可以是：带原任务与实际初稿的复核文本，以及仍明确标注一条“待修改”的交接记录。工具不要求把所有项目标成通过才能保存。

## 使用与文件格式

1. 填写任务信息，或载入明确标注的合成示例。目标、交付格式和验收标准必填；未知项保持未知。
2. “生成任务单”提供执行版与复核版 Markdown，可预览、复制或下载。
3. “生成协作计划”提供单步执行；研究/写作还可选择“计划 → 初稿 → 复核”。代码任务仅支持单步。修改目标或材料时使用新的任务包标识。
4. 审阅任务包后交给自己的本地执行器。没有执行器时，使用 Markdown 逐条交接；本站不分发同舟的个人执行器、会员设置或凭证。

| 文件 | 用途与约束 |
|---|---|
| 交接记录 JSON（新增） | `kind: task-brief-handoff`、`schemaVersion: 1`；保存任务、阶段产物、版本关联、人工判断和保留的旧记录。最大 512 KiB；每阶段产物最多 20,000 字符，每条验收依据最多 4,000 字符。使用“恢复交接记录”，不能导入草稿入口。原文件和规范保存格式均检查大小。 |
| 草稿 JSON | `kind: task-brief`、`schemaVersion: 1`；恢复任务信息。最大 128 KiB，未填完也可下载；包含原始表单材料，请妥善保存。工作流标识和流程方式不随草稿保存，恢复后需重新确认。 |
| 工作流 JSON | `schema: tongzhou.workflow`、`version: 1`，包含 `tasks` 与 `notice`；1 或 3 步，`route:auto`，依赖按顺序排列，末步保留显式验收。供执行器整包验证后入队，不能作为草稿导入。 |
| Markdown | 给执行者或复核者阅读的任务文本，不用于恢复本页输入，也不会自动执行。 |

所有导入都在当前浏览器内读取，先验证再确认替换。取消、坏文件、类型错误和超限保留当前内容。旧草稿 v1 仍可恢复原来的任务表单，同时使现有手动交接失效但保留原稿；恢复交接记录则同时恢复任务与完整交接状态。两种文件不可混用。

编辑任务信息、替换示例或清空表单会清空原任务单/本地工作流的旧预览，手动交接原稿仍保留并标明失效；修改工作流选项也须重新生成计划。下面的本地工作流限制不适用于手动交接提示词。

单步提示词最多 2400 个 Unicode 码位；三阶段复核提示最多 1950 个码位，为上游初稿预留空间。超限会拒绝生成，不静默删除材料；Markdown 仍受原表单长度限制。阶段标记仅用于推进流程，不证明内容正确。

## 能力边界

- 输入仅暂存在当前标签页。关闭标签页或浏览器限制可能造成丢失；已有产物时请下载交接记录并确认保存成功，只有任务信息时可下载草稿。保存失败有明确提示，当前内存内容仍可下载。没有云同步；明暗偏好与网站共用 `site-theme`。
- 复制给其他 AI 后，内容由该服务处理；先确认材料可以分享，不填写密码、密钥或私人档案。
- 文本约束不是安全沙箱，不能保证其他 AI 遵守要求。引用材料不当作更高优先级指令，任务单也不代替实际验收。
- 不自动选模型、执行队列、联网检索或测算额度。尚无外部用户效果或节省比例的验证。
- “通过”是使用者的人工记录，不是平台认证。导入文件中的通过标记也不证明真实检查已经发生；版本关联只用于发现本页修改造成的失效。任务未知项原样保留，不会自动结清。

## 本地运行与验证

从仓库根目录启动静态服务器，访问 `/tools/task-brief/`，无需安装依赖或构建。需支持 ES modules、原生 dialog 与浏览器存储；不要直接双击 HTML。

```sh
python3 -m http.server 8080 --bind 127.0.0.1
node --test tools/task-brief/core.test.mjs tools/task-brief/draft.test.mjs tools/task-brief/workflow.test.mjs tools/task-brief/handoff.test.mjs
```

`core.mjs` 生成任务单，`draft.mjs` 处理原草稿，`workflow.mjs` 生成本地执行器任务包。`handoff.mjs` 是手动交接纯函数与格式校验，`handoff-ui.mjs` 负责交接界面与标签页存储，`app.mjs` 连接任务表单及下载。页面复用相邻 `evidence-brief/app.css` 与站点字体，单独拷贝目录时需保留相对资源。
